# 菜单7 视觉采集与轮廓点序方法
本次是局部替换，不是恢复或覆盖整个工程。普通白色道路回退先尝试轮廓点序分解；缺边、孔洞、复杂拓扑不可信时回退原逐行算法。黑线优先和环岛/出口专用选路保留。
文档方法的全局方向角和画面边缘补边没有直接移植。采用完整点链、左右分弧、逐行内边界及局部多行聚合，继续输出原有归一化误差。
config/patrol_test.yaml 的 contour_order_enabled: 1 开启新方法；设0恢复旧轮廓计算。普通速度、转向及入环动作参数没有改动。
菜单7 -> 1：零轮速、腿高0.15m、低头25度，每5秒拍一组；0退出。输出 log/camera_capture。
菜单7 -> 2：调用既有实车巡线流程，确认后站立，再输入1开始；2停车、3任务重置、0退出。输出 log/driving_capture/时间_编号。
每次采集目录包含 raw.avi、frames.csv、summary.json、provenance.json、initial_config.yaml、各实际使用配置快照和 samples 图片。完整目录交给分析者；最好同时录制外部车辆视频并说明遥控/搬车时刻。
录像按处理帧保存，名义30fps；真实采集时间以CSV的capture_monotonic为准。队列满时丢弃采集帧，不阻塞控制；summary包含丢帧和错误，不能把视频帧数当作全部摄像头帧数。调试图只保存本帧实际绘制的图，不冒用旧图。
采集只覆盖进入控制计算的帧，不包含全部站立等待或暂停画面。采集失败会记录错误，车辆仍按既有控制运行；出现磁盘错误应停车并查看信息。
离线使用 python3 ros2_ws/src/wheel_robot/scripts/offline_contour_replay.py 采集目录；不启动ROS或底盘，生成白色道路旧/新方法对照。仅比较感知，不模拟车辆运动或声称可完赛。
验证重点：偏移起步、直道、急弯、缺边、反光、蓝色孔洞、环岛、横道；核对错误换路、压线和处理帧率，不只看输出率。
