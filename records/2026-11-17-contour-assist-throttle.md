# 轮廓改为纯辅助：拐点关闭 + 观测节流，恢复控制环频率

数据：`20261117_195000_36176`（278 帧 / 23.5 s，丢线 52.2%）。用户反馈“修改完之后转弯都转不过去了”。

## 定位：控制环被拖慢到约 12fps

- CSV 控制时间戳：共 278 帧、23.47 s → **11.8 fps**，dt 中位数 85.6 ms；此前无轮廓的采集是 ~24 fps。
- `observe_blue_road` 离线单帧约 **15.3 ms**（Python 逐行扫蓝带 + road_masks 连通域），加上原视觉 30~45 ms，主控制环被拖到 ~12 fps。0.3 m/s、2.0 rad/s 下 86 ms 的指令延迟足以让车“转不过弯”。
- 同时拐点拉线在低置信度道路路径上误触发：f128–129 `source=road conf=0.04` 却套了 `corner_entry_pull`（w 被拉成 -0.16/0.00，而车正在右转），f44 也有一次；拐点状态每 2 s 冷却后可能再次触发，和右转抢方向。

## 决定（按用户建议）

**恢复“黑线巡线为主”，轮廓只做辅助防丢线：**

- `contour_corner_enabled: 0`：拐点拉线关闭（保留代码/单测，后续标定后再开）；
- `contour_takeover_enabled: 1`：仅在黑线丢失时短时接管，要求蓝走廊 + 与最近黑线 near/mid 差 ≤0.30 + 距黑线 ≤0.35 s + 总时长 ≤0.60 s；
- 新增 `contour_update_seconds=0.15`：轮廓观测**最多 6~7Hz**，并且只在
  “黑线无效 / 最近 0.6 s 内黑线丢过 / 拐点模式开启”时才计算；其余帧复用缓存，正常巡线不再为轮廓付出每帧 15 ms；
- 接管/拐点仍用缓存观测，不会因为节流而失去状态。

## 预期

- 正常巡线控制环恢复到 ~20+ fps（与之前一致），转弯延迟恢复；
- 轮廓只在丢线瞬间接管 ≤0.6 s，避免“丢线直接冲出去”；
- 拐点不再干扰转向；后续若要重开，需要先解决蓝胶带配对（跨帧跟踪）和“只在可靠车道触发”。

## 验证

- 配置：`contour_corner_enabled=0`、`contour_takeover_enabled=1`、`contour_update_seconds=0.15`；
- 单测/整表 YAML 同步；完整测试见下。
