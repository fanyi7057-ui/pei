# 左探失败后立即左找 + 找线转向强度 0.80→1.10

数据：`20261116_191441_12843`（115.7s，丢线28.1%）、`20261116_191702_13989`（100.6s，丢线21.2%）。两段都用本轮 runtime `c3c868…`。

## 观察

1. **左探结束后有约 0.5s 的“直行空档”**：ENTRY 释放后的第一帧是 `mode=roundabout_entry_release`、`v=w=0`；随后 14 帧 `path_memory_bridge`，`w=0`、`v` 从 0 斜坡到 0.30；直到第 262 帧才进入 `active_search` 左转 0.80。旧流程里 `loss_command` 是释放时的 `(0,0)`，所以桥接段既不转也不快走。
2. **左找强度只有 0.80 rad/s**：0.30 m/s 下半径 0.375 m，环口一带不够；两段里从丢线到重获常见 1.5~2.5s。中间丢线（如 191702 的 f144、191441 的 f393）也是同样的右/左找 0.80，要 51/155 帧才回来。
3. 1517441 的 ENTRY 在 893-906 只持续约 0.4s，896/900 帧已有 `vv_entry_tracked_dashes`；释放后线已到右侧（near +0.77），车先向右再向左大幅摆动，环口被绕开。

## 改动

- `patrol_test.yaml`：`search_turn_rad_s` 0.80→**1.10**；`roundabout_search_turn_rad_s` 0.8→**1.10**。仍受 `max_turn_rad_s=2.0` 约束；入环左探仍用独立的 `roundabout_entry_turn_rad_s=1.20`。
- 新增 `roundabout_entry_search_seconds=0.80`：`_release_ring` 的失败来源以 `entry` 开头时，设置 `entry_search_until` 和 `entry_search_side=+1`；`entry_search_active()` 只在 `SEEK` 且未过期时为真。
- 节点：路径无效且窗口内时，`search_direction` 直接取左，跳过 0.8s 的默认找线等待；不确认路线、不延长环岛任务、不改速度/横道/终点凭据。
- 暂停顺延该窗口；真实 `visual_exit` 和非 entry 失败都会清空它。

## 验证

- 路由测试：失败左探启动 0.8s 左找、到期失效、非 entry 失败不启动、visual_exit 清空。
- 节点测试：先喂一帧有效路径建立“曾经有线”，再连续丢线；失败左探窗口内最终发布角速度 >0.5（旧流程第一帧后仍是 0 直行）。
- 完整测试：738 passed / 23 failed / 11 skipped；23 项与修改前历史/合同失败完全相同，无新增功能失败。

## 边界

- 1.10 只应配 `search_recovery_speed_m_s=0.30` 使用；若以后提高找线速度，半径会变大，需要重新对照。
- 这是“搜回能力”，不是入口几何本身。入口仍要求发散左支/环内路线证据；本改动不会让没有证据的探左无限延长。
- 未实车验证。先看重复段：ENTRY 后是否立即左转（不再有 `v=0,w=0` 的桥接帧）、丢线重获时间是否缩短。
